# 実行例

偽の Backlog（`tests/fakes.py`）につないで動かしたときの実際の出力です。
状況ごとに、実行から結果までを通しで載せています。

使い方の説明は [README.md](../README.md) を参照してください。

実行した時刻は **2026-10-01 09:30** とし、プロジェクトでは次の変更があったものとします。

| 日時 | 課題 | 変更 |
|---|---|---|
| 09-28 15:00 | PROJ-110 設計書レビュー | 件名・詳細を変更 |
| 09-30 09:10 | PROJ-123 ログイン画面のエラー表示 | 作成 |
| 09-30 10:00 | PROJ-98 帳票レイアウト修正 | 状態を変更 |
| 09-30 11:00 | PROJ-123 | 担当者を山田に |
| 09-30 13:00 | PROJ-98 | 担当者を佐藤から山田に |
| 09-30 14:00 | PROJ-105 問い合わせ対応 | コメント |
| 09-30 15:00 | PROJ-120 重複登録（テスト） | 作成し、5 分後に削除 |
| 09-30 17:00 | PROJ-98 | 状態・期限日を変更 |
| 09-30 18:00 | PROJ-1（記録先） | コメント（対象外） |
| 10-01 09:00 | PROJ-105 | 担当者を佐藤から鈴木に |

---

## 初回

記録先にまだ記録が無いので、 **前日（09-30）だけ** が対象です。まず `--dry-run` で確かめます。

```
$ .venv/bin/python backlog_change_log.py --dry-run
記録先: PROJ-1 変更記録（記法: markdown）
追跡するプロジェクト: PROJ
出力済みの最新の日: なし（初回）

===== 2026-09-30 に投稿するコメント（--dry-run のため投稿しません）=====
## 2026-09-30 の課題の変更

作成 1 件 / 更新 2 件 / 削除 1 件

### 作成

| 課題 | 件名 | 種別 | 状態 | 担当者 |
|---|---|---|---|---|
| PROJ-123 | ログイン画面のエラー表示 | バグ | 未対応 | 山田 |

### 更新

| 課題 | 件名 | 種別 | 状態 | 変更した項目 | 担当者 |
|---|---|---|---|---|---|
| PROJ-98 | 帳票レイアウト修正 | タスク | 処理済み | 状態、担当者、期限日 | 山田 |
| PROJ-105 | 問い合わせ対応 | 質問 | 処理中 | コメント | 佐藤 |

### 削除

| 課題 | 件名 |
|---|---|
| PROJ-120 | 重複登録（テスト）（当日作成） |

---
対象日: 2026-09-30

===== 当日の変更（コメントには書きません）=====
## 2026-10-01 の課題の変更（0:00〜09:30 時点）

作成 0 件 / 更新 1 件 / 削除 0 件

### 更新

| 課題 | 件名 | 種別 | 状態 | 変更した項目 | 担当者 |
|---|---|---|---|---|---|
| PROJ-105 | 問い合わせ対応 | 質問 | 処理中 | 担当者 | 鈴木 |
```

読みどころ:

- PROJ-98 は 3 回更新されましたが **1 行** です。項目名は最初に変わった順に重複なく並びます
- PROJ-123 は作成した日に担当者も変わりましたが、「作成」だけに載ります
- PROJ-105 の担当者は、10-01 に鈴木へ変わりましたが、 **09-30 の終わりの値（佐藤）** が載ります
- PROJ-98 の状態は 09-30 に 2 回変わりました（未対応 → 処理中 → 処理済み）。その日の終わりの **処理済み** が載ります
- 記録先の PROJ-1 へのコメントは載りません

`--dry-run` を外すと、同じ本文が記録先の課題にコメントとして投稿されます。

```
$ .venv/bin/python backlog_change_log.py
記録先: PROJ-1 変更記録（記法: markdown）
追跡するプロジェクト: PROJ
出力済みの最新の日: なし（初回）
2026-09-30 のコメントを投稿しました。

===== 当日の変更（コメントには書きません）=====
（以下、上と同じ）
```

## 毎日実行している場合

前日分が出力済みなら、コメントには何も投稿せず、当日分だけを表示します。

```
$ .venv/bin/python backlog_change_log.py
記録先: PROJ-1 変更記録（記法: markdown）
追跡するプロジェクト: PROJ
出力済みの最新の日: 2026-09-30
コメントに出力する日はありません。

===== 当日の変更（コメントには書きません）=====
## 2026-10-01 の課題の変更（0:00〜09:30 時点）
（以下、当日分）
```

## 実行を忘れた日がある場合

出力済みの最新の日が 09-27 なら、 **09-28・09-29・09-30 を 1 日ずつ** 投稿します。

```
$ .venv/bin/python backlog_change_log.py
記録先: PROJ-1 変更記録（記法: markdown）
追跡するプロジェクト: PROJ
出力済みの最新の日: 2026-09-27
2026-09-28 のコメントを投稿しました。
2026-09-29 のコメントを投稿しました。
2026-09-30 のコメントを投稿しました。

===== 当日の変更（コメントには書きません）=====
（以下、当日分）
```

変更が無かった 09-29 も、目印を残すために投稿されます。

```
## 2026-09-29 の課題の変更

変更はありませんでした。

---
対象日: 2026-09-29
```

## 7 日を超えて実行しなかった場合

出力済みの最新の日が 09-20 なら、前日から遡った **直近 7 日（09-24〜09-30）だけ** が対象です。
それより古い日は出力せず、Exit code `3` を返します。

```
$ .venv/bin/python backlog_change_log.py --dry-run
記録先: PROJ-1 変更記録（記法: markdown）
追跡するプロジェクト: PROJ
出力済みの最新の日: 2026-09-20
⚠ 2026-09-21〜2026-09-23 は上限 7 日を超えたため出力しません。

===== 2026-09-24 に投稿するコメント（--dry-run のため投稿しません）=====
## 2026-09-24 の課題の変更

変更はありませんでした。

---
対象日: 2026-09-24
（以下、2026-09-30 まで 1 日ずつ）
$ echo $?
3
```

## 投稿に失敗した場合

2 日目の投稿で通信が切れた例です。 **再送はせず** 、そこで止めます。

```
$ .venv/bin/python backlog_change_log.py
記録先: PROJ-1 変更記録（記法: markdown）
追跡するプロジェクト: PROJ
出力済みの最新の日: 2026-09-27
2026-09-28 のコメントを投稿しました。
エラー: 2026-09-29 のコメントの投稿に失敗しました: 通信断
  残りの日は次回の実行で出力されます。
$ echo $?
1
```

次に実行すると、出力済みの最新の日が 09-28 になっているので、09-29 から再開します。

## 複数のプロジェクトを追跡する場合

`config.yaml` で 3 つのプロジェクトを追跡した例です。PROJ の変更は上の表の一部、SUPPORT ではコメントと
状態・カスタム属性の変更があり、INFRA では変更がありませんでした。

```yaml
target:
  issue_key: "PROJ-1"
  project_keys: [PROJ, SUPPORT, INFRA]
```

```
$ .venv/bin/python backlog_change_log.py --dry-run
記録先: PROJ-1 変更記録（記法: markdown）
追跡するプロジェクト: PROJ, SUPPORT, INFRA
出力済みの最新の日: なし（初回）

===== 2026-09-30 に投稿するコメント（--dry-run のため投稿しません）=====
## 2026-09-30 の課題の変更

対象: PROJ, SUPPORT, INFRA

作成 1 件 / 更新 3 件 / 削除 0 件

### PROJ

作成 1 件 / 更新 1 件 / 削除 0 件

#### 作成

| 課題 | 件名 | 種別 | 状態 | 担当者 |
|---|---|---|---|---|
| PROJ-123 | ログイン画面のエラー表示 | バグ | 未対応 | 山田 |

#### 更新

| 課題 | 件名 | 種別 | 状態 | 変更した項目 | 担当者 |
|---|---|---|---|---|---|
| PROJ-98 | 帳票レイアウト修正 | タスク | 処理中 | 状態 | 山田 |

### SUPPORT

作成 0 件 / 更新 2 件 / 削除 0 件

#### 更新

| 課題 | 件名 | 種別 | 状態 | 変更した項目 | 担当者 |
|---|---|---|---|---|---|
| SUPPORT-42 | 問い合わせ対応 | 質問 | 処理中 | コメント | 佐藤 |
| SUPPORT-43 | 障害の調査 | バグ | 処理済み | 状態、対応チーム | 鈴木 |

### INFRA

変更はありませんでした。

---
対象日: 2026-09-30

===== 当日の変更（コメントには書きません）=====
## 2026-10-01 の課題の変更（0:00〜09:30 時点）

対象: PROJ, SUPPORT, INFRA

変更はありませんでした。
```

読みどころ:

- 1 日 1 件のコメントの中で、プロジェクトごとに見出しが分かれます
- 変更が無い INFRA も、見出しと「変更はありませんでした。」が載ります
- カスタム属性（対応チーム）は属性名のまま載ります

どれか 1 つのプロジェクトで変更が欠けているかもしれない日は、その日ごと投稿しません。

```
⚠ SUPPORT: 2026-09-28〜2026-09-29 はアクティビティを遡りきれず、不完全な可能性があるため出力しません。
```

## 応答を確かめる

`check_api.py` は読み取りだけで、項目名と件数を表示します。

```
$ .venv/bin/python check_api.py
接続先: https://myteam.backlog.com/api/v2
API キーの持ち主: 記録用ユーザー（ID 7）
記録先の課題: PROJ-1（ID 1000）
記録先のプロジェクト: PROJ（ID 10、記法: markdown）
出力済みの最新の日: なし（初回の扱いになります）

アクティビティ（PROJ、ID 10）: 直近 7 日分を 12 件読みました
  最も古いもの: 2026-09-28 15:00
  作成（種別 1）: 2 件
  更新（種別 2）: 6 件
  コメント（種別 3）: 2 件
  削除（種別 4）: 1 件
  一括更新（種別 14）: 1 件
本文のあるコメント（content.comment.content）: 2 件

変更された項目（changes[].field）:
  assigner: 3 件 → 担当者
  status: 2 件 → 状態
  limitDate: 1 件 → 期限日
  priority: 1 件 → 優先度
  summary: 1 件 → 件名
  description: 1 件 → 詳細

前提の確認:
  ✓ 担当者の変更は `assigner` として返っています
  ✓ 状態の変更は `status` として返っています
  ✓ コメントの本文は content.comment.content に入っています
  ✓ 一括更新の形: content: ['changes', 'link'] / link[]: ['id', 'key_id', 'title']
  - 種別の変更が期間内に 1 件もありませんでした。`issueType` で返るかは確かめられていません。--days を延ばすか、種別を変えてから再実行してください
  - コメントの文字数の上限は、読み取りだけでは確かめられません（本ツールは 20000 字で分けています）

結果: 前提と違う応答はありませんでした
```

この例には、上の表に加えて 09-29 の一括更新（優先度の変更）が含まれています。
