# backlog_change_log

Backlog のプロジェクトで、**どの課題が作成・更新・削除されたか**を、1 日ごとに特定の課題のコメントへ記録するスクリプトです。

- 前日までの変更を、**1 日（JST の 0:00〜24:00）につき 1 件のコメント**として投稿します
- 載せるのは、課題・件名・**変わった項目名**・**その日の終わりの担当者**です。誰が更新したか、値が何から何に変わったかは載せません
- 当日の変更は**標準出力に表示するだけ**で、コメントには書きません
- 記録先の課題そのものの変更は、記録の対象から外します

## 出力する日

| 状況 | 出力する日 |
|---|---|
| 初回（記録先にまだ記録が無い） | 前日だけ |
| 2 回目から | 出力済みの最新の日の翌日〜前日 |
| 上の期間が 7 日を超える | 前日から遡った直近 7 日だけ。それより古い日は出力しない（警告を表示） |

出力済みかどうかは、記録先の課題のコメント末尾にある `対象日: YYYY-MM-DD` の行で判定します。判定の対象は、**API キーの持ち主が投稿したコメント**だけです。

> [!WARNING]
> `対象日:` の行は手で書き換えたり消したりしないでください。消すとその日が未出力として扱われ、書き換えると別の日が出力済みとして扱われます。

実行を忘れた日があっても、次に実行したときに古い日から 1 日ずつ投稿します。投稿に失敗したらそこで止め、残りの日は次回の実行で出力します。

## コメントの例

```markdown
## 2026-09-30 の課題の変更

作成 1 件 / 更新 2 件 / 削除 1 件

### 作成

| 課題 | 件名 | 担当者 |
|---|---|---|
| PROJ-123 | ログイン画面のエラー表示 | 山田 |

### 更新

| 課題 | 件名 | 変更した項目 | 担当者 |
|---|---|---|---|
| PROJ-98 | 帳票レイアウト修正 | 状態、担当者、期限日 | 山田 |
| PROJ-105 | 問い合わせ対応 | コメント | 佐藤 |

### 削除

| 課題 | 件名 |
|---|---|
| PROJ-120 | 重複登録（テスト）（当日作成） |

---
対象日: 2026-09-30
```

- **1 日に何度更新されても、課題ごとに 1 行**です。変わった項目名を、最初に変わった順に重複なく並べます
- コメントだけが書かれた課題は「更新」に載り、項目名は「コメント」になります
- 作成した日に更新もされた課題は「作成」だけに載せます。作成した日に削除された課題は「削除」だけに載せ、「（当日作成）」と付けます
- 担当者と件名は**その日の終わり時点**の値です。翌日以降に変わっていても、その日の値を載せます。担当者がいなければ「未設定」、後日削除されて分からなければ「不明」です
- 変更が無い日も「変更はありませんでした。」と投稿します。投稿しないと、その日が出力済みにならないためです
- プロジェクトの文字の書式が Backlog 記法なら、同じ内容を Backlog 記法で書きます
- 長すぎる日は複数のコメントに分けます。`対象日:` の行は最後のコメントだけに付けます

## 準備

Python 3.10 以上と PyYAML が要ります。足りない場合は、起動時に何が足りないかを表示して終了します（終了コード `2`）。macOS 標準の `/usr/bin/python3`（3.9）では動きません。

```bash
python3 -m venv .venv
```

```bash
.venv/bin/pip install pyyaml
```

設定ファイルを作り、`space_host` と `target.issue_key`（記録先の課題）を書きます。調べるプロジェクトは、記録先の課題のプロジェクトです。

```bash
cp config.example.yaml config.yaml
```

API キーは設定ファイルに書かず、環境変数 `BACKLOG_API_KEY` か `.env` に置きます。

```bash
cp .env.example .env
```

## 使い方

まず `--dry-run` で、投稿される内容を確かめます。投稿はしません。

```bash
.venv/bin/python backlog_change_log.py --dry-run
```

問題なければ投稿します。

```bash
.venv/bin/python backlog_change_log.py
```

| オプション | 内容 |
|---|---|
| `--config` | 設定ファイルのパス（既定: スクリプトと同じ場所の `config.yaml`） |
| `--dry-run` | 投稿するコメントを表示するだけで、投稿しない |
| `--debug` | API リクエストを表示する（API キーは表示しない） |

定期実行（launchd / cron など）の設定は、このツールの範囲外です。

## 注意

- 変更は Backlog の**プロジェクトのアクティビティ**から読みます。課題一覧からは削除された課題が分からないためです
- アクティビティを遡りきれず、ある日の変更が揃っているか確かめられない場合、その日は投稿せずに警告します。記録先の課題の作成まで遡れていれば、揃っているとみなします
- コメントの投稿は、失敗しても再送しません。通信断の後に再送すると、投稿済みだった場合に同じコメントが二重に残るためです

## 構成

| ファイル | 役割 |
|---|---|
| `backlog_change_log.py` | 入口（引数の解釈、設定の読み込み） |
| `change_log/runner.py` | 通しの処理 |
| `change_log/client.py` | Backlog API（GET はリトライする。POST はしない） |
| `change_log/marker.py` | `対象日:` の行、出力済みの最新の日、出力する日の決定 |
| `change_log/collect.py` | アクティビティの取得、課題ごとの出来事への展開、日ごとの集約 |
| `change_log/state.py` | その日の終わりの件名・担当者の逆算 |
| `change_log/render.py` | コメント本文（マークダウン / Backlog 記法）と分割 |
| `change_log/config.py` | 設定ファイルと API キー |
| `change_log/runtime.py` | Python の版と依存の確認（3.9 でも読める書き方に保つ） |

## 開発

```bash
.venv/bin/pip install -e '.[dev]'
```

```bash
.venv/bin/python -m pytest -q
```

本物の Backlog に接続せずに実行例を見るには、偽の Backlog につなぐ `scripts/demo.py` を使います。投稿もしません。

```bash
.venv/bin/python scripts/demo.py run
```

`main` にすると入口から設定の読み込みまで通し、`main post` にすると偽物への投稿まで通します。
